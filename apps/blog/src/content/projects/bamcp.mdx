I spent the first few years of my career at
[Fulgent Genetics](https://www.fulgentgenetics.com/), building software for clinical genomics. A lot
of that work was around variant curation: giving scientists the tools they needed to inspect evidence
and turn it into a clinical report.

I've been looking for an excuse to revisit that world.

BAMCP started as an experiment with MCP: what would it look like if a model working with genomic
data could actually inspect the reads rather than getting a pileup translated into text first?

The result is a small MCP server built around BAM and CRAM files. It can inspect coverage and
candidate variants, look up external context, and render an interactive pileup directly inside
Claude.

## What it does

The main tool is `visualize_region`, which renders the aligned reads at a locus as an interactive
pileup. Mismatches, insertions, deletions, and soft clips are visible directly in the conversation,
and the view can be panned and zoomed without leaving Claude.

BAMCP also exposes tools for:

- coverage at a region
- candidate variants in the reads
- gene lookup
- ClinVar annotations
- gnomAD population frequencies
- a combined variant-curation summary

Underneath, it's Python and `pysam`/htslib, exposed through FastMCP. It works with indexed local
files as well as remote BAM and CRAM files over HTTP or S3.

## A BRCA2 example

This is HG00096, one of the 1000 Genomes samples, at a region in BRCA2.

BAMCP finds a homozygous non-reference allele and renders the underlying reads inline. From there,
Claude can pull the gnomAD frequency—roughly 52%—and see that this is a common polymorphism rather
than something interesting simply because it happens to be in BRCA2.

The useful part isn't Claude producing that conclusion. It's that the reads, coverage, allele
balance, and external annotations are all available in the same interaction.

## Using it

A typical session is pretty close to the workflow I remember from genomics tools.

Start with a gene, coordinate, or candidate variant. Look at the reads. Check whether coverage is
reasonable. See what non-reference alleles are actually present. Then pull in ClinVar and
population-frequency data where it's useful.

BAMCP doesn't try to make a clinical pathogenicity call. That's intentionally outside its scope. It
exposes the evidence and gives the model tools for navigating it.

There are plenty of ways an automated interpretation can still go wrong: low coverage, poor allele
balance, an over-interpreted ClinVar assertion, or population frequency being treated as more
meaningful than it is. Having the underlying data available doesn't solve those problems, but it
does make it much easier to see where an answer came from.

## Connect it to Claude

BAMCP runs as a hosted remote MCP server, so there's nothing to install locally.

Server URL:

```
https://bamcp.rtrentjones.dev/mcp
```

In claude.ai:

1. Open **Customize → Connectors**, then **+ → Add custom connector**.
2. Paste the URL and click **Add**.
3. Complete the OAuth sign-in.
4. Enable BAMCP from **+ → Connectors** in a conversation.
5. Give it a public BAM or CRAM URL and a locus to inspect.

The interactive pileup requires a client with
[MCP Apps support](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude),
including claude.ai, Claude Desktop, and the mobile apps. Other MCP clients can still call the
underlying tools; they just won't render the viewer.

## A few implementation details

The pileup is an HTML5 Canvas MCP App rather than a generated image or screenshot. That matters
because the interface stays interactive: reads can be inspected, regions can be navigated, and the
model and user are working from the same view.

The server runs on an Oracle Cloud Ampere instance behind a Cloudflare Tunnel. The infrastructure is
Terraform-managed, and the deployment has a small MCP-level integration test that connects to the
deployed server, lists its tools, calls one, and checks authentication behavior.

Mostly, though, this project has been an excuse to work with genomic data again and to see what
these newer agent interfaces are good for outside the usual coding and productivity examples.
