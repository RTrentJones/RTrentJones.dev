I spent the first few years of my career at
[Fulgent Genetics](https://www.fulgentgenetics.com/), building software for clinical genomics. A lot
of that work was around variant curation: giving scientists the tools they needed to inspect evidence
and turn it into a clinical report.

I've been looking for an excuse to revisit that world.

BAMCP started as an experiment with MCP: what would it look like if a model working with genomic
data could actually inspect the reads rather than getting a pileup translated into text first?

The result is a small MCP server built around BAM and CRAM files. It can inspect coverage and
candidate variants, look up external context, and render an interactive pileup directly inside
Claude.

## What it does

The main tool is `visualize_region`, which renders the aligned reads at a locus as an interactive
pileup. Mismatches, insertions, deletions, and soft clips are visible directly in the conversation,
and the view can be panned and zoomed without leaving Claude.

BAMCP also exposes tools for:

- coverage at a region
- candidate variants in the reads
- gene lookup
- ClinVar annotations
- gnomAD population frequencies
- a combined variant-curation summary

Underneath, it's Python and `pysam`/htslib, exposed through FastMCP. It works with indexed local
files as well as remote BAM and CRAM files over HTTP or S3.

## A BRCA2 example

This is HG00096, one of the 1000 Genomes samples, at a region in BRCA2.

BAMCP finds a homozygous non-reference allele and renders the underlying reads inline. From there,
Claude can pull the gnomAD frequency—roughly 52%—and see that this is a common polymorphism rather
than something interesting simply because it happens to be in BRCA2.

The useful part isn't Claude producing that conclusion. It's that the reads, coverage, allele
balance, and external annotations are all available in the same interaction.

## Using it

A typical session is pretty close to the workflow I remember from genomics tools.

Start with a gene, coordinate, or candidate variant. Look at the reads. Check whether coverage is
reasonable. See what non-reference alleles are actually present. Then pull in ClinVar and
population-frequency data where it's useful.

BAMCP doesn't try to make a clinical pathogenicity call. That's intentionally outside its scope. It
exposes the evidence and gives the model tools for navigating it.

There are plenty of ways an automated interpretation can still go wrong: low coverage, poor allele
balance, an over-interpreted ClinVar assertion, or population frequency being treated as more
meaningful than it is. Having the underlying data available doesn't solve those problems, but it
does make it much easier to see where an answer came from.

## Connect it to Claude

BAMCP runs as a hosted remote MCP server, so there's nothing to install locally.

Server URL:

```
https://bamcp.rtrentjones.dev/mcp
```

In claude.ai:

1. Open **Customize → Connectors**, then **+ → Add custom connector**.
2. Paste the URL and click **Add**.
3. Complete the OAuth sign-in.
4. Enable BAMCP from **+ → Connectors** in a conversation.
5. Give it a public BAM or CRAM URL and a locus to inspect, or use one of the built-in demo
   datasets: `demo:HG002` (GIAB, GRCh38) or `demo:HG00096` (1000 Genomes, GRCh37).

### Try this

If you don't have a BAM handy, these prompts work against the demo datasets as-is:

- *"Using BAMCP, list the contigs in demo:HG002, then show me the reads at
  chr17:43099900-43099930 and tell me what variant is there."* A heterozygous G>A in BRCA1 at
  43,099,914, with the reads to back it up.
- *"With BAMCP, check whether the T>G at chr17:43096151 in demo:HG002 is real."* This site is
  filtered out of the default calls; the curation summary explains why, rating it a high artifact
  risk because every supporting read is on one strand and most of their bases are low quality.
- *"Find BRCA2 in demo:HG00096 with BAMCP and summarize its coverage."* The gene lookup detects that
  this sample is on GRCh37 and that its contigs are named `13` rather than `chr13`.

BAMCP also ships an `explore_demo` prompt that walks through the same ground step by step.

The interactive pileup requires a client with
[MCP Apps support](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude),
including claude.ai, Claude Desktop, and the mobile apps. Other MCP clients can still call the
underlying tools; they just won't render the viewer.

## Does the picture actually help?

I wanted to know whether showing a model the pileup changes its answers, so I ran a
pre-registered evaluation in four rounds. Sites were shown to three model sizes as raw read
text, as BAMCP's structured evidence, as the rendered pileup, or as the pileup plus the text.
The sites included synthetic variants and artifacts and, from the third round on, real sites
from the GIAB HG002 sample, with truth from the GIAB benchmarks and the coordinates disguised.

It doesn't, at least not on these sites. In the third round the reads as text were the best evidence (99% right on the
real sites), and adding the picture to them changed nothing. The picture on its own was a usable
but weaker substitute: 87–89%, about as good as the structured summary, and overconfident when it
was wrong. The largest model did read pictures almost perfectly; the smallest did not.

A fourth round went looking for harder cases, where text alone would get only about 70% right,
so a gain would have room to show. Real sites from the classes that trip up short-read callers
(low-fraction variants, caller false positives, duplicated genes) did not produce them: the
models were at 94–96% even from raw `samtools mpileup` output. Only one kind of site was hard:
insertions and deletions inside long single-letter repeats, where the sequencer's own slips look
like a real variant. On 60 fresh sites of that kind, neither BAMCP's text tools nor the picture
raised overall accuracy, and both made the smallest model miss more real variants. The picture
did one thing the text did not: the larger models were about twice as likely to call the
genotype (one copy or two) correctly when they could see the reads.

That round also showed why BAMCP's text was not helping. It raised a homopolymer warning on
every indel in a repeat, real or not, and it counted the variant against every read at the site,
including the many reads that end partway through the repeat and so cannot show its length. Both
now depend on the reads that cross the whole repeat: the warning appears only when the called
length is rare among them, and the variant's share is measured among them. Re-run on the same 60
sites, BAMCP's text took accuracy from 84% to 91%, with all three models better, and the number
of real variants given the right genotype rose from 13 of 90 to 42 of 90. Those are the sites
that prompted the change, so this result is exploratory until a fresh round confirms it.

A fifth round, registered before any site was drawn, repeated the comparison on 90 sites that no
earlier round had seen, from new scans of four more chromosomes. BAMCP's text took accuracy from
83% to 89%, and real variants given the right genotype rose from 30 of 135 to 54 of 135. Both
results were the ones the plan named in advance, and both held. The gain comes from
heterozygous variants, which the models no longer mistake for low-fraction ones; homozygous
variants in long repeats are still usually called heterozygous, and that is the next thing to
fix.

The evaluation did change the viewer. An early round showed that colouring every base hid
homozygous variants, so reads are now grey with only the mismatches coloured. The
[write-up](https://github.com/RTrentJones/BAMCP/blob/main/docs/eval/visual-results.md) has the
numbers and the caveats. For BAMCP, that means the viewer is for the person, and the model keeps
getting the reads as text.

## A few implementation details

The pileup is an HTML5 Canvas MCP App rather than a generated image or screenshot. That matters
because the interface stays interactive: reads can be inspected, regions can be navigated, and the
model and user are working from the same view.

The server runs on an Oracle Cloud Ampere instance behind a Cloudflare Tunnel. The infrastructure is
Terraform-managed, and the deployment has a small MCP-level integration test that connects to the
deployed server, lists its tools, calls one, and checks authentication behavior.

Mostly, though, this project has been an excuse to work with genomic data again and to see what
these newer agent interfaces are good for outside the usual coding and productivity examples.
