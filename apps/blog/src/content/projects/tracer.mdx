> Tracer is a place to keep benchmark and eval results after the CI run that produced them is gone.
> Today it holds pg_kafka's conformance and benchmark history.

## Why it exists

I wanted benchmark history to outlive the CI log it appeared in. Tracer is the small persistence and
UI layer for that: a run lands in Postgres and shows up as a trend instead of disappearing behind a
green check.

Where it stands today: the dashboard is deployed and holds **real runs from pg_kafka's benchmark
pipeline** — its normalized conformance and performance scores land here on each tagged release.
I'm wiring the other tools' `eval` and browser-agent runs into it next, so for now it remains a
prototype with one real source of data.

## What's in it now

- pg_kafka's conformance pass-rate per tagged release
- its normalized benchmark scores, on the same cadence
- the commit SHA and verification timestamp behind each point
- enough metadata to click a chart point back to the run that produced it

## The stack

- **Next.js on Vercel**, backed by **Neon** Postgres — a branch per env (prod + beta), so beta evals
  never touch the prod record. (It's the first deployed tool on Greenlight's Neon backend.)
- **Schema as code** — migrations run on the build against Neon's direct connection; the pooled
  connection serves the app. Prod and beta hit different branches by design.
